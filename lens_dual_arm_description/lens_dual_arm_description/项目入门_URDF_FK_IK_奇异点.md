## 1. 先建立全局认知：这个项目在做什么

`lens_dual_arm_description` 的核心目标不是“只显示一个机器人模型”，而是：

- 用 `URDF/MJCF` 描述双臂结构和关节约束；
- 用 MuJoCo 做一个“可信赖的几何/运动学参考真值”；
- 让你在 `user_fk.py` 里写自己的 FK，并和仿真真值对比；
- 用 `left_arm_ik_slider.py` 做实时 IK 求解（含奇异点与多解策略）；
- 用 `left_arm_path_planner.py` 把 IK 接到 RRT-Connect 路径规划流程。

一句话：这是一个“机械臂运动学验证与算法迭代脚手架”。

---

## 2. URDF 的作用：它不是算法，但决定了算法成立的前提

## 2.1 URDF 在这个项目里的职责

URDF（`urdf/lens_dual_arm_description.urdf`）主要负责描述：

- **拓扑结构**：哪些 `link`，哪些 `joint`，父子关系是什么；
- **几何信息**：`visual/collision` 的 mesh；
- **动力学参数**：`inertial`（质量、惯量）；
- **关节约束**：转轴方向、上下限、速度/力矩限制。

URDF 本身不“求解 FK/IK”，但 FK/IK 的数学模型完全依赖 URDF 的几何定义（关节轴、连杆偏置、坐标系关系）。  
所以常见问题是：算法写对了，结果不对，根因其实是模型坐标定义不一致。

## 2.2 这个双臂 URDF 的关键特征

- 左右臂各 7 个转动关节（7DoF），冗余度高（做 3D 位置任务时有多解）；
- 末端在项目中用的是：
  - 左臂：`Left_Wrist_Pitch_Link`
  - 右臂：`Right_Wrist_Pitch_Link`
- 左右夹爪还有 `prismatic` 关节（不在当前 IK 主回路里）；
- 每个关节有 `limit`，IK/规划都依赖这些范围约束。

---

## 3. 为什么项目主流程优先用 MJCF，而不是直接用 URDF

当前脚本主要加载 `mjcf/mj_lens_dual_arm.xml`，原因很实际：

- MuJoCo 对 MJCF 支持最直接，兼容性最稳定；
- URDF 的 mesh 路径在不同环境下容易解析失败；
- 项目里 FK/IK 脚本依赖 MuJoCo API（`mj_jacBody`, `xpos`, `xquat`）做实时计算与验证。

结论：  
**URDF 是“规范描述与生态兼容入口”，MJCF 是“当前项目的执行入口”。**

## 4. 正运动学（FK）怎么理解、怎么在本项目落地

## 4.1 FK 的本质

给关节角 `q`，求末端位姿 `T_base_to_ee(q)`。  
通常输出：

- 位置 `pos = [x, y, z]`
- 姿态 `quat = [w, x, y, z]`（本项目统一这个顺序）

## 4.2 你在本项目里要做什么

在 `user_fk.py` 实现：

- `fk_left(q)`
- `fk_right(q)`

输入：7 维关节角（弧度，顺序严格按注释）  
输出：`(pos, quat)`

## 4.3 怎么验证你写的 FK 对不对

运行：

```bash
python fk_viewer.py
```

脚本会：

- 从仿真读取当前左右臂关节 `q`；
- 读取仿真末端位姿（真值）；
- 调用你的 `fk_left/fk_right`；
- 打印位置误差和姿态误差（四元数角误差）。

建议验收标准（工程实践）：

- 位置误差稳定在 mm 级（`1e-3 m`）以内；
- 姿态误差在 `1e-3 ~ 1e-2 rad` 量级；
- 全关节范围随机抽样都不过大误差。

## 5. 逆运动学（IK）怎么理解、怎么在本项目落地

## 5.1 IK 的本质

给目标末端位姿（本项目当前是目标位置 `x_d`），反求关节角 `q`。  
机械臂是非线性系统，通常用迭代数值法，而不是一次闭式解。

## 5.2 项目当前 IK 是“位置 IK”

在 `left_arm_ik_slider.py` 中，主求解变量是末端位置误差：

- 误差：`e = x_d - x(q)`（3维）
- 雅可比：`J = ∂x/∂q`（`3x7`）

用的是阻尼最小二乘（DLS）：

`dq = J^T (J J^T + λ^2 I)^(-1) e`

然后每次迭代更新 `q <- clamp(q + dq)`，直到误差足够小或达到迭代上限。

## 5.3 为什么要阻尼（DLS）

普通伪逆在奇异附近会数值爆炸。  
DLS 相当于给逆算子“加软正则”，牺牲一点精度换稳定性，特别适合在线控制与滑条交互场景。

## 6. 奇异点：是什么、怎么判断、项目里怎么处理

## 6.1 奇异点直观理解

当机械臂某些姿态下，末端某些方向几乎“动不了”或“要靠巨大关节变化才能动一点点”，就是接近奇异。  
数学上表现为 Jacobian 退化（秩下降，最小奇异值接近 0）。

## 6.2 项目里的奇异性指标

`left_arm_ik_slider.py` 使用了两类信息：

- 条件数 `cond(J) = s_max / s_min`（越大越危险）；
- 可操作度近似 `manip = sqrt(det(JJ^T))`（越小越危险）。

并在终端输出 `Cond(J)`，当过大时打印 warning。

## 6.3 项目里的奇异点处理策略（已经实现）

- **自适应阻尼**：`λ = base + gain/(manip + eps)`，越接近奇异阻尼越大；
- **步长裁剪**：`dq` 每轴限幅（`step_clip`），防止一帧跳太大；
- **关节限位钳制**：每次更新后 `clamp` 到 `q_min/q_max`。

这三件事组合后，能显著减少“抖动、跳变、发散”。

## 7. 多解问题：为什么会出现、项目里怎么选解

## 7.1 多解来源

7DoF 做 3D 位置任务，约束只有 3 维，天然冗余（自由度多于任务维）。  
同一个末端位置，可以对应多组关节角（典型如“肘上/肘下”分支）。

## 7.2 项目当前的多解处理（`solve_left_ik_multi`）

代码策略是：

1. 构造多组初值 seed（当前姿态、中位姿态、两组肘部偏置）；
2. 每组 seed 跑一次局部 DLS；
3. 按综合代价选最优解。

代价大致是：

- 末端残差（优先级最高）
- 平滑项（离上一帧越近越好）
- 限位代价（离边界太近会被惩罚）

这样做的效果：

- 减少“跳解”；
- 保持动作连续；
- 更少撞关节边界。

## 8. 零空间（Nullspace）偏置：冗余机械臂的关键技巧

对 7DoF 来说，你可以在不破坏主任务（末端位置）的情况下，利用零空间做次任务。  
本项目次任务是“远离关节限位中点偏置”：

- 计算一个偏置方向 `bias = (q_mid - q)/span`
- 投影到零空间：`dq_null = k * (I - J^+J) * bias`
- 与主任务增量相加：`dq = dq_task + dq_null`

意义：

- 让解更“健康”，避免长时间贴边；
- 让后续规划更有余量；
- 增强连续运行稳定性。

## 9. 路径规划如何接在 IK 后面（项目完整链路）

`left_arm_path_planner.py` 流程：

1. UI 给出目标 `Goal XYZ`；
2. 先用 IK 求一个 `q_goal`；
3. 若 IK 误差过大（不可达或数值失败）直接报错；
4. 若 IK 可行，在关节空间做 RRT-Connect；
5. 对路径做 shortcut 平滑 + densify 插值；
6. 逐点下发到位置控制器执行。

注意：

- 当前规划只做关节限位约束；
- 尚未加入自碰撞/环境碰撞检测；
- 更适合“算法联调验证”，不是最终避障版。

## 11. 常见坑与工程建议

- **坐标系不一致**：FK 和仿真误差很大时，先查 joint axis 和 link 原点定义；
- **四元数比较方式错误**：注意 `q` 与 `-q` 表示同一姿态，比较时要取绝对点积；
- **奇异附近抖动**：提高阻尼、减小步长、增加零空间权重通常有帮助；
- **多解跳变**：提高平滑项权重，且 seed 要包含“上一帧解”；
- **不可达目标**：应给出“最近可达投影”或清晰报错，不要硬迭代到发散。
