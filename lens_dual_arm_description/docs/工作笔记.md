# LENS 双臂项目 — 工作笔记

> 本文档系统性记录本仓库涉及的技术、实现思路、职责边界、联调中的典型问题与处理方式，便于复现与交接。  
> 操作手册级步骤见 [README.md](README.md)、[lens_dual_arm_description/README.md](lens_dual_arm_description/README.md)、[lens_dual_arm/README.md](lens_dual_arm/README.md)。

---

## 1. 项目目标（我们到底在做什么）

| 层级 | 目标 |
|------|------|
| 仿真 | 在 MuJoCo 中验证双臂运动学、IK、关节空间轨迹规划，并做身体/自碰相关避障。 |
| 虚拟对齐 | 在不接真机时，按《电驱通讯协议》或 `actuator_SDK` 语义输出「将要下发的命令」，便于和文档、抓包对照。 |
| 真机 | 通过 ROS2 把仿真得到的关节角（或内部动作序列）送到 `joint_controller_node`，经 EtherCAT + MIT 模式驱动实体电机。 |
| 工程化 | 解决静态库与系统库 ABI 不一致、root/sudo 与 ROS 发现、关节映射与符号约定等联调问题。 |

## 2. 技术栈总览

| 技术 | 在项目中的角色 |
|------|----------------|
| **MuJoCo 3.x** | 加载 MJCF、正逆运动学辅助（雅可比）、`mj_geomDistance` 碰撞/间隙检测、可视化。 |
| **NumPy** | 向量/矩阵运算、规划与 IK 中的数值计算。 |
| **Python `tkinter`** | IK 与路径规划脚本的滑条 GUI（系统包 `python3-tk`）。 |
| **阻尼最小二乘 IK** | 3D（位置雅可比）与 6D（位置+姿态雅可比）实时求解；多初值、限位与奇异处理。 |
| **RRT-Connect** | 左臂关节空间路径规划（自实现，非 OMPL 依赖）；shortcut 平滑 + 轨迹加密。 |
| **自碰/身体避障** | `LeftArmBodyCollisionChecker`：对指定几何对做符号距离与分段采样（含按关节步长自适应）。 |
| **CAN 协议（MIT 0x0B）** | `motor_can_protocol.py`：浮点量化、`pack_std_mit_non_broadcast` 等与《电驱通讯协议》对齐。 |
| **RealTimeBridge** | `realtime_bridge.py`：`can` / `ethercat` 两种打印模式，EtherCAT 侧读 `actuator_config.json` 做 joint→slave 映射提示。 |
| **ROS 2（Jazzy 等）** | `sensor_msgs/JointState` 话题；`rclpy` 在仿真侧轻量发布；`rclcpp` 在控制器节点。 |
| **actuator_SDK（静态库）** | `ActuatorController`：EtherCAT 初始化、`setTargetMit` 批量 MIT、enable/mode 等。 |
| **SOEM（经 SDK）** | EtherCAT 主站与 PDO 周期通信（由 SDK 封装）。 |
| **fmt / spdlog** | SDK 或示例链路的依赖；**版本需与 `libactuator_controller.a` 编译时一致**，否则链接或运行期 ABI 错误。 |
| **Docker** | 固定 Ubuntu + ROS + 指定 fmt/spdlog 版本，隔离编译 `joint_controller_node`。 |

## 3. 分模块：如何实现 & 起什么作用

### 3.1 模型与运动学基座

- **文件**：`lens_dual_arm_description/mjcf/*.xml`、`meshes/`、`urdf/`、`mj_kinematics_env.py`
- **实现**：统一在 `DualArmKinematicsEnv` 中加载 MJCF，定义左右臂 7 关节**命名顺序**（与 URDF 关节名一致），供 FK 与脚本引用。
- **作用**：所有 IK/规划脚本共享同一套关节顺序，避免「第几个元素对应哪一台电机」混乱。

### 3.2 逆运动学（IK）

- **文件**：`left_arm_ik_slider_3d.py`（仅位置）、`left_arm_ik_slider.py`（6D）、`right_arm_ik_slider.py`、`dual_arm_ik_slider.py`
- **实现要点**：
  - 3D：3×7 位置雅可比 + DLS。
  - 6D：`mj_jacBody` 平移 + 旋转；姿态误差用旋转矩阵对齐；自适应阻尼与步长；多组初值。
- **作用**：交互调姿态、给规划器提供目标关节、双臂同时解算时合并为 14 维命令（`dual_arm_ik_slider.py`）。

### 3.3 路径规划与避障

- **文件**：`left_arm_plan_collision.py`、`left_arm_path_planner.py`、`left_arm_slider_trajectory.py`
- **实现要点**：
  - 碰撞：`mj_geomDistance` 得到有符号距离；`clearance_min`、边上插值采样；`segment_valid_by_step` 等控制采样密度。
  - 规划：RRT-Connect → shortcut → `densify_path`；失败时打印诊断（起终点最近距离、冲突几何对、`t` 参数等）。
- **作用**：在有关节限位与身体避障的前提下生成可执行关节轨迹；`left_arm_slider_trajectory.py` 集成 3D IK + 规划 + 自动执行 + 虚影预览。

### 3.4 虚拟协议桥接（不接 ROS）

- **文件**：`motor_can_protocol.py`、`realtime_bridge.py`
- **实现**：环境变量切换 `LENS_BRIDGE_PROTOCOL=can|ethercat`，按设定频率打印 CAN 帧或 SDK 式批量 MIT 说明；EtherCAT 模式可解析 JSON 映射。
- **作用**：仿真与真实报文格式「对齐验收」，不依赖网口与 root。

### 3.5 ROS2 仿真 → 话题

- **文件**：`left_arm_ik_slider.py`、`left_arm_slider_trajectory.py`、`right_arm_ik_slider.py`、`dual_arm_ik_slider.py` 中的 `Ros2JointCommandPublisher`（或等价类）
- **实现**：`LENS_ROS_BRIDGE=1` 时创建 `JointState` 发布者，按 `LENS_ROS_HZ` 限频；`name` + `position`（rad）。
- **作用**：把当前指令关节角送到中间件，供真机节点订阅。

### 3.6 真机执行节点（C++）

- **路径**：`lens_dual_arm/src/lens_arm_controller/`
- **实现要点**：
  - CMake：`ENABLE_ACTUATOR_SDK` 打开时链接 `libactuator_controller.a`、`libsoem.a` 及匹配版本的 **fmt/spdlog**。
  - 运行时：`initCanIdAndEthercatRelation`、设 MIT 模式、`enableMotor`、`setTargetMit`。
  - 参数：`ethercat_control.yaml` 中网口名、JSON 路径、`mit_kp`/`mit_kd` 等。
- **作用**：ROS 与 EtherCAT 之间的执行层。

> **注意（与联调强相关）**  
> 本仓库当前 `joint_controller_node` 源码：**订阅 `/joint_states`，发布 `/joint_command`**，在内部动作回放等路径调用 `sendJointCommandToEthercat`。  
> Python 侧默认向 **`/joint_command` 发布**外部轨迹。若要让「仿真直连电机」，必须保证存在**订阅该话题并转发到 SDK** 的逻辑（扩展节点或中继）。详见根目录 [README.md](README.md) 说明。  
> 若你本地另有分支已实现「外部 `/joint_command` 订阅」，以实际分支为准，并在本笔记中自行增补一行记录。

## 4. 联调中遇到的问题与处理（问题 → 原因 → 解决）

### 4.1 构建与环境

| 问题 | 原因 | 处理 |
|------|------|------|
| `AMENT_TRACE_SETUP_FILES: unbound variable` | `set -u` 下 source ROS 脚本引用未定义变量 | 在容器脚本中 source 前后临时 `set +u`。 |
| 构建报错路径指向不存在的 `/home/lens/...` | 环境变量残留（旧 Docker/他人工作区） | `unset` 相关 `AMENT_PREFIX_PATH`、`COLCON_PREFIX_PATH` 等后重新 `source` 再 `colcon build`。 |
| `undefined reference` 到 spdlog/fmt 符号 | `libactuator_controller.a` 与系统 libfmt/libspdlog **ABI 不一致** | Docker 内固定编译 **fmt 8.1.1**、**spdlog 1.9.2**（与 Dockerfile 一致），CMake 显式链接该前缀；运行期 `LD_LIBRARY_PATH` 包含自定义 `lib`。 |
| `libfmt.so.8: cannot open shared object file` | 运行时未找到容器内构建的共享库 | 从容器 `docker cp` 出 `/opt/third_party/lib` 到宿主机目录并加入 `LD_LIBRARY_PATH`。 |

### 4.2 EtherCAT 与权限

| 问题 | 原因 | 处理 |
|------|------|------|
| `Could not initialize EtherCAT master` / 无 socket | 网口名错误、网线未插、接口 DOWN、非 root | `ip -br link` 确认接口；参数 `ethercat_ifname` 与实际一致（如 `enp12s0`）；通常需 **sudo**。 |
| `sudo: ros2: command not found` | sudo 重置 PATH | `sudo -E bash -lc 'source ...; ros2 run ...'`，或使用 `ros2` 绝对路径。 |
| ROS log `Permission denied` | root/用户混用默认 log 目录 | `export ROS_LOG_DIR=/tmp/ros_log`（可写路径）。 |
| `getifaddrs` / `shared memory` 权限错误 | 无权限访问网络或 DDS 共享内存 | EtherCAT 侧通常整体用 **sudo**；必要时统一 **RMW** 与 **ROS_DOMAIN_ID**。 |

### 4.3 ROS2 发现与通信

| 问题 | 原因 | 处理 |
|------|------|------|
| 仿真发布话题，控制器 `rx_count` 不增 | 域不一致、或 Fast DDS 共享内存跨用户异常 | 双方统一 **`ROS_DOMAIN_ID`**；尝试 **`RMW_IMPLEMENTATION=rmw_cyclonedds_cpp`**；发布与订阅用同一终端网络环境。 |
| 控制器收不到指令但 `ros2 topic echo` 正常 | 订阅的不是同一话题或节点未订阅外部命令 | 核对 topic 名、QoS；确认执行节点是否订阅仿真发布的话题（见 §3.6）。 |

### 4.4 电机与 MIT 参数

| 问题 | 现象 | 处理 |
|------|------|------|
| `mit_kp`/`kd` 过小 | 只有电流声、几乎不动 | 逐步提高 `kp`（及适当 `kd`），直到能跟随；具体数值与机械有关，需在安全范围内试。 |
| `setMotorMode` / `enableMotor` 部分失败 | 单轴故障、时序、或总线负载 | 日志定位 CAN ID；部分场景可改为「失败仍继续」避免整机关闭 EtherCAT（视安全策略而定）；单轴逐步测试。 |
| 某关节报错 `0x08` | 驱动器报错（过载/跟踪等，以手册为准） | 单轴小步测试；降低指令变化率/发布频率；检查该轴机械与方向映射。 |

### 4.5 关节映射与命令语义

| 问题 | 原因 | 处理 |
|------|------|------|
| 单关节测试「动的总是 1 号关节」 | `JointState` 只带一个名字时，下游按**固定槽位**填向量，未按**名字**对齐 | 测试脚本发 **完整 7 或 14 维** `name`+`position`；控制器侧按 **`joint_name_` 重排**再 `setTargetMit`（若已实现）。 |
| 仿真与真机某关节转向相反 | 模型 `axis` 与电机/编码器符号约定不一致 | 在**执行层**对列出的关节名做**位置取反**（如参数 `invert_joint_names`），以实测为准标定列表。 |

### 4.6 Python 仿真环境

| 问题 | 处理 |
|------|------|
| 无 `tkinter` | `sudo apt install python3-tk` |
| 无 `mujoco` | venv 内 `pip install mujoco`；与 `rclpy` 并存时可用 `--system-site-packages` 或先 source ROS |
| PEP 668 禁止系统 pip 直装 | 使用项目 venv，勿对系统 Python `pip install --user` 强装 |

## 5. 系统性经验总结

### 5.1 分层排错顺序（推荐）

1. **模型与命名**：MJCF 中关节名、顺序与 `actuator_config.json` 一致。  
2. **纯仿真**：无 ROS 跑通 IK/规划。  
3. **终端桥接**：`RealTimeBridge` 打印是否与协议文档一致。  
4. **ROS 环回**：同一用户 `ros2 topic echo` / `hz` 确认发布。  
5. **跨进程/ sudo**：DOMAIN_ID、RMW、`LD_LIBRARY_PATH`、网口与权限。  
6. **单轴→联动**：先每轴小步，再轨迹；最后调 `kp/kd` 与限频。

### 5.2 「方向反了」到底依据什么

- **不是**从某 PDF 读错表得到的。  
- **是**对比「仿真指令符号」与「真机肉眼观察转动方向」后的**实测标定**；在执行层做符号翻转，使 MuJoCo 与实体一致。

### 5.3 文档与代码同步

- 每次改默认参数（MIT、话题名、避障阈值）应同步更新 `README` 与本笔记「已知问题」或「版本说明」。  
- 若合并了「外部 `/joint_command` 订阅」分支，务必改掉 §3.6 的「当前源码」描述，避免误导。

## 7. Docker 一体化镜像（分发与复现）

| 项 | 说明 |
|----|------|
| 目的 | 在任意装有 Docker 的机器上 `pull` 后获得与构建机一致的 ROS2 + 仿真 + 已编译 `joint_controller_node`（`ENABLE_ACTUATOR_SDK=ON`）。 |
| 构建 | 仓库根目录：`./docker/build-image.sh` 或见 [docker/README.md](docker/README.md)。 |
| 上下文 | **必须**在含 `lens_dual_arm_description`、`lens_dual_arm`、`actuator_SDK_X86` 的仓库根执行 `docker build`。 |
| 排除项 | `.dockerignore` 默认去掉 `grpc/` 等大目录；真机仍需 `--network host` / `--privileged` 及正确 `ethercat_ifname`。 |
| 参数文件 | 容器内使用 `/opt/lens_project/docker/ethercat_control.docker.yaml`（绝对路径，避免宿主机中文路径问题）。 |
